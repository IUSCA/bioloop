About

The Center runs shared sequencing instruments and the analysis pipelines built around them. Every run is registered in Bioloop so that raw reads, assemblies, and variant calls stay linked to the sample manifest they came from.

Working with us

Submit a project request through the intake form. Turnaround for a standard WGS run is ten working days from sample receipt. Runs are scheduled on the Monday after the manifest is approved.

Why the order differs

Each reader is on the page for a different reason, so a different thing earns the space above the fold. The page structure does not change — a summary band, then a wide panel and a thin one. What changes is which cards are in them and in what order.

ReaderHere toGets the space above the fold
Signed out Read what this group is, cite it, or find a way to contact it. Arrived from a paper or a search. The profile prose, and the citation at the top of the thin column. There are no actions to displace it. The band carries no facts: group.view_profile answers an anonymous caller with the public profile attributes alone, and those include neither created_at nor the ancestors, so there is nothing a cell could hold. Admin names appear without emails, by the same policy.
Member Find and use the group's data, and work out what they are allowed to do. The profile, and a two-item action panel. Member uploads stays in the band because it is the fact that decides whether New dataset is even offered. Settings they cannot change are dropped. Admins sit below the fold with a line saying what to ask them for.
Admin Decide the things only they can decide, then change settings. A needs attention row — invitations awaiting a reply, access requests to review — above everything else in the wide column, and the five-item action panel beside it. Both sit between the band and the profile, so an admin never scrolls to find work. The profile follows, because an admin already knows what the group does.

The rule behind it

  • A fact earns its cell only if the reader can act on it or is bound by it. That is why the band has four cells for an admin, three for a member, and two for a visitor, rather than one row hidden behind permission checks.
  • Attention before description. Anything waiting on the viewer outranks anything merely describing the resource. Only an admin has such a thing, so only an admin's page starts with one.
  • The attention row renders only when the count is non-zero. A row reading 0 requests to review is worse than no row: it takes the best position on the page to say nothing.
  • Reference material sinks. The citation is first for a visitor and last for an admin, for the same reason in both cases — it is what that reader is least likely to need next.

The shape of the page

Three parts, in this order, for every role and for both groups and collections.

  • Summary band. One card under the tabs: the description on the left, the facts that matter to this reader in a single row beside it.
  • Wide panel. What this resource is. Cards may be full width or paired side by side.
  • Thin panel, 320 px. What the reader can do and how to refer to the resource: quick actions, links, citation.

The two panels are always both present, including on a resource with no profile written. The wide panel then holds the profile prompt and the admins card, so the width stays used and the page does not reflow into a different layout for an empty state.

As built

The layout above is implemented in GroupOverviewTab.vue and CollectionOverviewTab.vue, over four new shared components in components/v2/overview/. Six things differ from what is drawn here.

  • The signed-out page is not built. The public profiles are separate components, and the band drawn for them cannot exist: group.view_profile answers an anonymous caller with the public profile attributes alone, which carry neither created_at nor the ancestors.
  • A collection's band has no owner-group cell. The collection page header already reads Owned by …, and the rule against repeating is not suspended for the band.
  • The who-has-access preview is not built. The Overview tab holds a grant count and no grants; drawing two rows needs a fetch the tab does not make.
  • A group has no "request access" action, because access requests target datasets and collections. A member of a group that forbids uploads therefore has an empty action panel, and the panel is dropped rather than rendered empty.
  • A collection's "request access" action now hides from a caller who can issue grants. It used to render for everyone. Somebody who can grant access to a collection does not need to ask for it.
  • "Create a subgroup" is new. It needed the subgroups tab to expose its modal and the page to route the action, which the other quick actions already had.
  • The member-uploads control is the metadata modal, not a switch in place. The modal already owns that setting and its explanation, and a second edit path would be a second thing to keep in step.

One defect surfaced on the way: the collection page declared canAddDataset on the Overview tab and never bound it, so Add a dataset could not appear for anyone. It is bound now.

What stays the same

  • The page header, the tabs, and every modal.
  • Every field that was on the page is still reachable. The counts moved to the tab bar, which was already showing them.
  • Group and collection Overview keep the same shape, so the two pages stay recognisably siblings.

Open questions for review

  • The needs-attention row is new. It reads counts the page already fetches — pending invitations on a group, pending access requests on a collection — and renders nothing when both are zero. Worth confirming that those are the only two things that should ever appear there.
  • Who-has-access on a collection previews two grants beside a link to the Access tab. It is the one place a preview of a tab's content survives, on the argument that who can read this is the question an admin of a restricted collection asks constantly. Delete it if that argument does not hold.
  • Admin emails are withheld from signed-out readers and shown to members. Confirm that matches what the public profile is meant to expose.
  • A member with no permissions has an empty action panel. The drawn member can upload, so the panel has two items; when a group forbids member uploads the panel should be dropped rather than shown empty, which moves the citation up.
  • Member Contrib. is relabelled Member uploads. The abbreviation existed to fit a 110 px column that is gone. Confirm the wording matches the switch elsewhere.
  • The facts row at narrow widths. Below roughly 1100 px the band should stack, description first and facts beneath, and the two panels become one column. The breakpoints have to be checked against the real ones in the app.
