Design Overview

§0

Visual language, information architecture, role model

🎨 Visual Language

  • IBM Plex Mono for labels, IDs, code; IBM Plex Sans for prose
  • High-contrast neutral palette — data-ink forward
  • Semantic colour: blue = data/access, green = active/granted, amber = warning/archived, red = revoked/danger, purple = collections
  • Tight density — governs large datasets; no decorative whitespace
  • Borders & rules for structure; shadows only for elevation (modals, tooltips)

🗂 Information Architecture — Top Level Pages

  • Groups — hierarchy, membership, archive
  • Datasets — ownership, grants, collections membership, lifecycle
  • Collections — dataset containers, grant targets
  • Grants — cross-resource grant dashboard & issue
  • Access Requests — workflow for request/approve/reject
  • Audit Log — immutable event stream
  • Platform Admin — super-admin only: users, unarchive, overrides

👤 Role-Sensitive UI

  • Platform Admin — sees everything, all actions enabled
  • Group Admin — full governance of own groups/datasets; read-only oversight of descendants
  • Member — sees group metadata & membership; no governance actions
  • Actions are rendered per-role; forbidden actions are hidden (not greyed) at query layer
  • Oversight-only views carry a visible "Read-only oversight" banner

⚡ Key UX Principles

  • Every access decision is explainable — "why does X have access?" surfaced inline
  • Archived groups render with a striped amber visual treatment everywhere they appear
  • Grant atomicity is abstracted via Presets; raw grants exposed in "Advanced" toggle
  • Dual-consent flows use a two-step confirm pattern with clear authority display
  • Audit trail linked from every material action's success toast
Scope of this spec: Groups · Datasets · Collections · Grants · Grant Presets · Access Requests (workflow) · Audit Log · Effective Access Explainability · Platform Admin. Excluded from v1: group reparenting, ownership transfer (dual-consent), grants preset management, access request renewal, dataset creation from UI, non-authoritative collections / saved sets.

Global Navigation

§1

Persistent sidebar, topbar breadcrumbs, role-sensitive items

The sidebar is the primary navigation surface. It collapses to icon-only at narrow viewports. The topbar provides contextual breadcrumbs and per-page actions. No global search in v1 — filtering is per-page.

Collections

§4

Audit Log

§7

Immutable event stream, per-resource audit, filterable timeline

Audit log is append-only and immutable. Accessible globally (all events I can see based on my governance authority) or scoped to a resource via the resource's Audit tab. Every material event (grant.created, grant.revoked, grant.expired, membership changes, archive/unarchive, collection mutations) emits a record.

Effective Access & Explainability

§8

"Why does X have access to Y?" — per-dataset and per-user views

Explainability is a hard system invariant, not just a UI feature. The UI exposes the minimal grant + membership chain that caused access. Available on Dataset → Effective Access tab, Group → Grants tab, and as a standalone query tool.

Super-admin panel: users, unarchive groups, incident response

Platform Admin panel is only rendered and accessible to users with the platform_admin role. All actions here are logged with "platform override" authority provenance. Designed for high-friction actions — no bulk operations without explicit confirmation.
